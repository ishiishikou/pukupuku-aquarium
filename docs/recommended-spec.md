# 推奨仕様：もう1問触りたくなる、小さな日課

ユーザーの「その方向で設計を見直す」という指示に基づく、次の試作の設計方針。楽しさを実証済みという意味ではない。以前の入力方式の広い比較より、以下の体験を優先する。仕様の正本は本稿、5問の制作・評価条件は[試作設計](five-puzzle-experience.md)。

## 届ける体験

「ひとつ気づく。数マスをぷくぷくと埋める。次に見る場所が分かる。気持ちよく終わり、もう1問触りたくなる」。

難問を制覇する達成感より、ほどよい発見と小さな手応えの反復を中心にする。一意性は必要な土台。最優先の評価は自発的な継続と、触っている時間の快さ。解答速度・タップ数・連続利用日数を最大化しない。

起動時は続きか新しい1問にすぐ入る。1問でやめても成立し、途中でも保存して戻れる。日課はユーザーが自然に選ぶ習慣を意味し、連続日数の喪失、限定報酬、毎日必須のノルマではない。

## 1問の流れ

| 場面 | プレイヤーの体験 | 設計 |
| --- | --- | --- |
| 入口 | まず見る場所がある | 0・満数・明瞭な水槽の幅など入口を少なくとも1つ作る。通常問題では強制ハイライトしない |
| 気づき | ここが分かった | 水平・下方向・幅と残数の比較による短い必然。仮置きを主役にしない |
| 入力 | ぷく、ぷく、と手応えが返る | 自分で判断したセルを入力。毎回短い応答。正解かどうかで感触を変えない |
| 次の発見 | さっきの判断が役に立つ | 数字の残数や隣接水槽へ推理がつながる問題を選ぶ |
| 終わり | きれいに整った | 短い泡と水面の落ち着き。長い待ち時間・タップ必須の祝福画面なし |
| 選択 | 続けても、やめてもよい | 「もう1問」「今日はここまで」を同等に提示。次問を自動開始しない |

通常問題は5×5を基準に設計し、必要な気づきのためにのみサイズを増やす。暫定の制作目安は1問に独立した気づき2〜4回、1回に続く入力2〜6マス。ただし水増しや自動ヒントで目安に合わせない。機械のログ項目数と人の気づき回数は同一ではなく、実際の間と入力の観察で調整する。1問1〜3分は初期の目安で、制限時間や合否基準にはしない。

## ルールと入力

現行Aquariumの行列数・水平・下方向の制約を維持。未確定／水／乾燥を区別する。初版では水路と動的な盤面変化を入れない。

基準版は水／乾燥モードを選んでセルをタップ。同状態を再タップで未確定へ戻す。水は入れる感触、乾燥は小さな泡を消すような控えめな感触とし、×の確定にも手応えを付ける。モードは文字・形・選択表示で常時見える。長押しや複雑なジェスチャーを必須にしない。

**タップの手応えは残すが、余分な入力を遊びの代わりにしない。** 水槽全体の自動充填は基準版に入れない。自分の小さな判断を入力する時間を残し、一括化の必要性は推理後の負担で判定する。

比較版は「水の入力だけで全制約を満たしていれば、残る乾燥マスをまとめて完了」を明示的に実行できる終盤補助に限定する。数が合っただけでは実行できず、全水槽の制約も検査する。全水マス確定を条件に出すため、部分盤面から答えを教える機能にはしない。補助操作は1回で取り消せる。採用は実験後、基準版は全マス手動確定を維持。

## 見え方と助け方

太い水槽境界と薄い内部線を分け、タップした水槽を短く強調する。色だけで領域を識別させない。未確定は空気として確定した見た目にしない。部分入力はメモとして描き、水平線を描く場合は同じ水槽の既に入力済みの水だけをつなぐ。未入力の答えを水面のアニメーションで先に見せない。

緑の数字は「水の数が一致」を示す。正解保証や全セル確定とは区別する。公開条件から分かる超過や確定セル同士の矛盾は控えめに知らせ、未入力の下に水がないことを誤答扱いしない。原版の誤答・復帰案内の上書きを改善版で直す。

ヒントは押したときだけ、(1)見る行と水槽、(2)使う理由、(3)具体的な結論、の順。結論を見ても自分で入力できる。例：「この行はあと1。横2マスの水槽は、同じ高さを一緒に水にするので入りません」。答えを開けただけで説明したことにしない。

## 触覚・泡・音と海の演出

受理された入力の時点に短い振動・泡・音を結ぶ。水／乾燥／取消は控えめに区別し、正誤・解への距離を振動に埋め込まない。長い振動、強すぎる成功音、連打時の重なりは避ける。水面が落ち着く短いクリア演出の途中でも、次へ進むか終了できる。

触覚候補の実装資料は[Apple Core Haptics](https://developer.apple.com/documentation/corehaptics)。APIとSDK・最小OS・実機挙動は実装段階で検証する。ここでは実装済みとしない。ブラウザ版は推理と操作の検証用であり、最終的な楽しさの判定はiPhone実機の触覚付きで行う。

音・振動・動きは独立設定。消音や動きを減らした状態でも全ルールを判断できる。クジラやカメは盤外かクリア後の短い景色として扱う。解答を遮らず、盤面を変えず、次の生き物を見るためにプレイを強要しない。初期5問には収集・通貨・育成・広告・ランキングを持ち込まない。

## 最初の開発判断

まず[5問の体験試作](five-puzzle-experience.md)を作る。任意の追加1問は継続意思を観測するために用意する。導入3問は本編前の短い練習として分離し、同じ難度で遊ぶ5問の評価に混ぜない。

自発的に続けたくなるか、推理後の入力が快いか、×の入力も気持ちよいかを確認する。快さの問題なら触覚と入力を、退屈なら問題構成を、理解不足なら導入とヒントを直す。毎回新しいルールを追加して解決しようとしない。

5問で継続したい理由を説明でき、実機でも確認できてから30問へ進む。水路や独自ルールは、基本体験に満足しているのに推理の変化が不足すると分かった場合に再検討する。数値と採否の詳細は試作設計に集約する。
